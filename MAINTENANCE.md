# Maintenance

`takeaway-skill` is maintained as a public, lightweight reference-distillation Skill.

The goal is to help users turn references into reusable mechanisms, pattern cards, adaptation routes, and implementation briefs without copying surface style or shipping private materials.

## What We Maintain

We actively maintain:

- README clarity
- Skill loading instructions
- `skill/SKILL.md` workflow guidance
- public-safe output boundaries
- `takeaway_is_here/` usage guidance
- public showcase wording
- documentation for Codex, Claude Code, and similar coding agents
- broken links, missing images, and unclear demo instructions
- contribution and issue guidance
- privacy, copyright, and public/private boundary wording

## User Feedback Sources

Feedback may come from GitHub issues, social media comments, video comments, direct usage reports, or early user testing.

If feedback comes from outside GitHub, it should not be presented as a GitHub issue unless an issue is actually opened. It can still be summarized in maintenance notes, changelogs, or future GitHub issues as external user feedback.

## Known Project Boundaries

This repository does not maintain:

- private prompt chains
- private research archives
- private design assets
- private client, student, or user materials
- third-party screenshots or recordings as bundled source packages
- copied surface designs from other people's work
- external hosted demo platforms as official project infrastructure
- commercial integration links unless explicitly reviewed and accepted
- large unrelated feature requests

## External Links And Hosted Demos

External demos or third-party wrappers can be useful for experimentation, but they are not automatically part of the official public repository.

Before an external link is added to the README, it should be reviewed for:

- public-safety
- privacy
- user trust
- copyright risk
- long-term availability
- whether it changes the project's maintenance burden

The default answer to unsolicited hosted-demo or commercial links is: thank you, not adopted for now.

## Maintenance Priorities

Current public maintenance priorities:

1. Keep the loading path simple.
2. Make the public/private boundary easy to understand.
3. Keep examples public-safe and non-copying.
4. Improve the `takeaway_is_here/` output workflow.
5. Keep the public package lightweight and source-readable.

## Feature Direction

Future improvements may include:

- clearer beginner prompts
- better public-safe examples
- improved showcase structure
- stronger documentation for output handoff
- better workflow checks before public release

Large features should be discussed in an issue before implementation.

# Public-safe downstream handoffs

Only hand off a compressed mechanism card after the approval gate passes. The receiver should not need the reference's full text, screenshots, or private notes.

## Required fields

- candidate ID and approved scope;
- target layer;
- strongest evidence type;
- adaptation direction;
- lock-first items;
- do-not-touch items;
- smallest valid result;
- stop-loss condition;
- human confirmation point.

## Web or interaction implementation

Name the layer (`hero`, `cursor`, `reveal`, `grid`, or similar), define expected states, and state the build order: skeleton, content, interaction, then decoration. Stop and return to evidence after two failed tuning rounds.

## Visual implementation

State the locked composition, crop, hierarchy, and allowed changes. Do not use a reference brand, signature typography, or protected asset as a shortcut.

## First-person writing

If the downstream task is a user's own script or first-person text, hand off only the user's confirmed facts and the approved abstract mechanism card. Never pass third-party raw text, line-by-line mapping, fixed paragraph order, or signature phrases.

## Rejection

If the resolver gate fails, return a candidate report with the reason and stop. Gallery visibility, a formal label, or a public demo selection cannot replace approval.
